## Findings

### F-001：Start/getter original 改为原生异常输送

- severity: n/a_re；status: implemented-and-offline-verified；confidence: high（仅本批两个 typed ABI）。
- evidence_ids: E-source、E-helper、E-broker、E-match。
- location: `ExactHookBroker.LocalInitializationIsolation.cs`、`NativeInitializationContextBridge.cs`、`InitializationContext.{h,cpp}`。
- impact: Prepare 取得原 trampoline，Configure 先保存不可变 original/managed callbacks，再 Commit 发布入口。native helper 调 original 时没有 CLR original delegate 帧，其 native finally 调 Exit 配对 TLS/observer/计数；原 SEH/C++ 异常继续交原生 caller。普通异常不被重新标成 LOCAL；LOCAL 异常使责任 unknown，getter abnormal 不执行正常返回/root callback。
- repro_steps: production fixture 以普通/LOCAL × Start/getter × SEH/C++ 共 8 条路径核对异常 code、typed payload、线程、native original entered/exited、callback 次数、后续 ordinary 调用与完整 in-flight=0；在完整 Runtime suite 与同包独立 runner 中均通过。getter 故障由嵌套原生 caller 捕获后才返回 managed observer，避免测试本身要求原异常穿越 CLR。
- remediation: 仅在两个 exact ABI 上使用新保证。Play/Progress/Timeline original 路径仍需各自异常输送审查，不能复制本 finding 的结论。

### F-002：回调故障与原异常责任分开

- severity: n/a_re；status: implemented-and-offline-verified；confidence: high（fixture 明确覆盖的路径）。
- evidence_ids: E-helper、E-bind、E-broker。
- location: native Enter/Exit 边界、Runtime exact TLS frame 与 Start observer 清理。
- impact: managed callback 异常在 reverse-P/Invoke 内包含；native helper containment 防止 Exit fault 覆盖正在展开的 original exception。拒绝 Enter 或 native Skip 不能伪造非 null 成功；getter Before/After/Fault 失败仍保持既有 abort/claim 规则。native 最外层活动包含 managed Enter 前与 Exit 后的窗口；独立 atomic 统计快照不比较非一致的 entered/exited 累计值。
- repro_steps: E-helper 的 Enter/Exit 故障、原 SEH/C++ 和 Exit 不覆盖原异常；E-broker 的 callback 异常/null abort、worker/递归、原异常后的 TLS 与计数恢复；E-bind 的发布失败、原异常与 ordinary observer 行为。不同层 fixture 的证据分别使用，不把 helper 的 1747 断言当成新增 1747 个生产 suite。
- remediation: 仍需实际游戏 prologue/metadata、并发安装与目标游戏原调用对照；排空不等于 future consumer 已结束。

### F-003：同一 run 的发布存储提前预留

- severity: n/a_re；status: implemented-and-partially-verified；confidence: high（存储及已测路径），medium（完整退休组合）。
- evidence_ids: E-source、E-publication。
- location: `NativeLocalRunTerminationBoundaryState.Record`、`ReservePending`、`PublishProgress`、`PublishInitializationController`。
- impact: 原 graph record 在 native 尝试前创建初始化/progress 两枚零 scalar token，保留固定五根槽和 32-slot 发布数组；actual native identity 只完成一次，检查后 Volatile 发布。发布后 token 不再变更，包括 unknown、退休、槽复用；这使 dictionary equality/hash 与读者持有的旧令牌保持稳定，不再 Append/Where 出新发布数组。
- repro_steps: 三组新增回归验证预留时 roots/native reads 为零，采用中 worker 看不到半成品，发布仍用原 token/数组，拒绝重写不改变 hash，progress slot 复用产生新 record/token 且旧 token 不变。现有 progress withdrawal 回归继续通过。
- remediation: 这不是全系统零 managed 分配；Runtime frame/args、backend 等仍可分配。新 fixture 未直接覆盖 controller map 的撤回、再排空与复用组合；历史 helper 临时 root、完整 I04 故障矩阵及 active consumer 退休仍须继续，不将 I04 或 B 项整项标完成。
