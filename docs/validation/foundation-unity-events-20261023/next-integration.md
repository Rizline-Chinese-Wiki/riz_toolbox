# 后续完整消费者协议

listener对象图和真实Invoke/Prepare快照只能说明观察到的本次分派，不能替代具体listener所转交工作的owner。下一步按实际捕获到的少量Target/Method逐项识别操作来源、异步转交和取消，不扩大为无界全游戏调用图。未知类型继续opaque/unsealed，不删除回调来制造完成。

先补固定版本Invoke内联Prepare与实际executing遍历的证据。独立List.Prepare观察没有该覆盖率；不能将它强制附到Invoke，也不能用错误InstanceVoid ABI hook共享RVA的Invoke()和Invoke(Object[])。应先确认实际调用点、精确MethodInfo/传参和可保真native transport，再给执行路径确认。

补齐Add/Remove/Clear/Dirty/重建等实际列表mutation历史，以及listener leaf的确切ABI、虚分派/泛型处理、原函数一次调用和原生异常展开。仅入口/出口快照相等不能排除Invoke内增删后恢复；persistent序列化候选不等于本次executing集合。

直接协程的GO销毁取消路径仍须取得engine的实际取消证据与未来来源封口，不能把未自然false的记录按计时/GO dead改完成。provider、外置Tween/Task/manager队列、结果按钮/commands、音频/信息进度图和借用资源也分别纳入实际owners。

同局future sources全部撤回或确切结束、globals/menu只条件恢复自己的值/信用、后继保留后，才由实际生产verifier组合证据走VerifyConsumersEnded→Close→bridge.TryRetire，最后bundle/reservation/handler/coordinator槽退休。逐个独立root只尝试一次free，未知保责任，不以重试覆盖未知结果。

完整Retry新建revision lease/bundle/Chart/JudgeData/run代次，Return使用真实scene/menu owner；Loader完整构造后按故障边界开放RequestPlay。其余SPEC B01–B19继续，不把目标缩为LOCAL或查分。游戏验证保持用户“实测稍后”的安排，与离线证据分开。
