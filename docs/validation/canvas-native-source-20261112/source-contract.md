# Canvas actual source: file evidence, 2026-11-12

This file contract reuses the unchanged hash-pinned GameAssembly and complete geometry evidence. `verify-canvas-profile.py` reads PE bytes, metadata dump and prior evidence; it never maps a DLL, invokes exports, starts or installs the game. `canvas-profile-verification.json` reports only those offline checks. Builds and runtime source tests are a separate root-agent validation.

`NativeSeekCanvasNativeProfile` composes `ISeekChartNativeProfile`; the production dependency is the existing clock/chart profile. There is no required Hold instance or Hold list. Its 7 unchanged complete spans total 4096 bytes: Canvas GetInformations/SetPosition/Start/Update, Progress ChartTimeRageToRealTime, GetEaseWithProgress and Vector3 .cctor. Runtime verification requires the same current MethodInfo, exact declared metadata and executable entry, every complete body and all 5 constants. It invokes none of those methods and reads no static values itself.

Actual slot order governs Canvas projection. `CanvasMove.index` is data, not an array remapping key. The exact fields are **xPositionKeyPoints at 0x18** and **speedKeyPoints at 0x20**. Both reference `List<KeyPoint>`; each point stores Single time/value at 0x10/0x14, Int32 easeType at 0x18 and Single floorPosition at 0x1c. Lists require complete current backing, size, version and all active points, with independently retained identities and bounded budgets.

CanvasControl reads LevelInformation at 0x20, CanvasMove[] at 0x28, Transform[] at 0x30 and Single screenWidth at 0x58. Range conversion is the exact native typo `ProgressControl.ChartTimeRageToRealTime(System.Double,System.Double) -> System.Single`, RVA 0x3fff90. A live call must independently validate non-byref argument and result layouts, retain the actual Progress/Information/Chart graph, and perform final managed guards after callback-capable operations. These file pins do not prove absence of invocation effects.

GetEase.EaseInfos is a static EaseInfor[] at 0; each entry stores Int32 code at 0x10 and Single[] progress at 0x18. The native easing helper lazily invokes Instantiation if the table is null. Actual capture must require an already initialized table and copy its actual complete values; it must not call either easing helper or initializer. Down/right are exact static readonly NativeVector3 fields at 0x24/0x3c. The complete cctor shows down=(0,-1,0), right=(1,0,0), but actual capture must use official exact static-value reads and compare the captured bits, not substitute those constants.

The numeric source retains strict reverse scans, range/floor multiply then add, Single span rounding before Double epsilon 1e-6, native ease-table interpolation, clamp and width, and floor*speed/down then x*right/add component order. Prior source references and constant reads remain pinned inputs.

Unresolved: live game source/readonly metadata/static-getter behavior, metadata/error/List helpers and range invocation effects, resolved Unity setters/callbacks, target Canvas writes and line/ring environment, renderer consumers, Hold engine exit, complete clock/Seek transaction and ABA exclusion. All runtime/target-environment/consumer/admission claims remain false. No old closed profile or old evidence is modified.
