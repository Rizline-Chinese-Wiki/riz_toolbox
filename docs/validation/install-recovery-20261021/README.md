# B19 安装失败与中断恢复

2026-10-21。范围只限 `Install.ps1`、`Install.Common.ps1`、`Uninstall.ps1` 和安装测试。未运行游戏、未重新构建产品、未修改实际游戏安装目录。691 包的实际安装记录保持原样。

## 可复现缺陷与修复

旧安装器只把旧、新文件的哈希写入 pending，再逐个原地替换文件。后续复制失败时已经替换的旧字节丢失，磁盘出现混合版本；再次读取 pending 又把已经换过的文件收为归属，并不能恢复整个旧集。

新合成夹具使用生产安装脚本，先正常安装 v1，再升级到不同内容的 v2，在 SDK 复制处抛出真实脚本异常。此前 loader 已替换。旧代码得到 **0/1**，报 `Known-good file was not restored: winhttp.dll`，见 `before.log`、`before/results.json`。最早一次夹具作用域错误保留在 `fixture-harness-initial.log`，不计产品回归。

修复顺序：

1. 先锁定安装目录，保持现有归属、路径和哈希预检。
2. 本次真正会改变的已有文件，独立备份到 `BepInEx/RizToolbox/install-recovery/<transaction-id>/<index>.bak`；旧字节验证并 Flush 后才发布 journal。
3. journal 原子写入，并继续保留原 `files` 归属。只有新 payload 和最终清单全部提交才算更新完成。
4. 普通异常立即回滚；强制终止留下的事务，在下次安装或卸载时，先恢复旧文件集，再检查新包/依赖或执行卸载。
5. 恢复先检查全部目标和备份。目标仅允许旧值、新值或缺失，备份必须匹配旧哈希；陌生修改、损坏/缺失备份和链接路径均拒绝，保留 journal 和备份供处理。
6. 首次安装没有旧文件时，回滚仅删除本次计划中仍匹配写入哈希的文件。用户编辑的配置和计划外文件保留。重复恢复接受此前已经恢复的旧文件，最后原子清空事务。

安装锁文件 `.riz_toolbox.install.lock` 留作稳定互斥对象，安装/卸载持有的操作系统锁会随进程退出释放。安装器自身的清单、备份目录和锁文件不能被包或清单当作普通 payload 认领；已有用户配置不进入写入计划。备份清理只删明确记录且哈希未改变的文件，不递归删除目录。

## 保留的限制

- 历史 pending 没有旧字节备份，无法凭哈希重建丢失版本。本实现明确警告，沿用仅接受记录字节的兼容恢复，不把旧历史升级为事务保证。
- 强制终止进程验证了 journal 顺序和恢复幂等，不代表真实断电、设备写缓存或磁盘坏块已验证。文件执行 Flush(true)，但没有声称整个多文件集合具备文件系统原子提交。
- 如第三方在中断后改动目标、备份损坏或磁盘继续不可写，恢复会具体报错并保留证据，不擅自覆盖用户内容或声称旧版本已可运行。
- 不自动启动游戏，不允许安装/卸载入口在检测到游戏运行时开始恢复。用户在更新过程中另行启动游戏的竞态未由本夹具覆盖。
- 该补丁仅补 B19 的安装事务缺口；干净系统、所有兼容/能力矩阵和真实游戏版本验证仍不算完成。
