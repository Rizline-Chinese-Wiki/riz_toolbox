发布路径为：复制有界请求/依赖 → 验证 DAG/格式 → 解析及配额检查 → scope.Own（尚未发布） → 复核取消、scope、parser代次、外部依赖身份 → 无回调区提交一份完整字典与修订。失败不增加发布修订；旧单项也经历这一完整路径。

撤回路径为：整组先移出发布字典 → 释放各发布引用 → 只有最后消费者释放才清理 payload → 成功后释放其依赖。一个根释放失败时该根及其依赖继续占配额，独立兄弟仍尝试清理；不重试可能已经部分执行的任意 IDisposable。阶段清理聚合失败并保留原来的 Cancelled/ContentInvalid 代码，信息包含未确认清理，不能静默当作释放成功。

错误线程拒绝发生在消费 release 委托之前，随后主线程仍可释放。模块停用时若有未确认根，保留 store；后续 Probe 返回永久不可用原因，要求进程重启，不用新 store 绕过原配额。对于正常但仍被旧消费者持有的根，Probe 暂时等待；最后消费者释放后才建立新 store，避免重复模块恢复绕过旧消费者额度。
