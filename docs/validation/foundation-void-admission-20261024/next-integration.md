# 下一步：把准入保护接成可用的生产安装路径

本批只交付已安装父入口后的调用准入，不把零计数当作首次安装许可。生产mid仍未发布，RequestPlay仍关闭。需要继续完成以下链路。

1. **取得首次执行屏障。** 现有Loader等GameAssembly出现后后台轮询安装runtime_invoke，实际UnityEvent父入口又在局部run准备时才安装；这两个时序都不提供全局排他。先检查固定Doorstop启动边界能否在IL2CPP初始化之前同步持有控制权，并明确其他线程和已经执行目标的处理。不能用一次线程枚举、旧回调计数为零或设置Ready标志替代证明。
2. **实现固定目标的发布事务。** 输入必须是固定构建、唯一函数范围、原始五字节和实际返回地址；先登记父hook/helper/relay/回调的永久责任。父入口准入关闭且Active0后再写，写前验证原字节与页属性，写后验证整条CALL、邻接字节、目标以及指令缓存。凡已开始写而结果未知，保留关闭和责任，不由Dispose放行。当前lease尚无“成功写后放行”操作；下一步应由固定installer私有签发完整发布结果，再准许恢复准入，不能公开一个可伪造的bool。
3. **联合故障回归。** 在真实native parent和真实mid上测试已进入/停车/退出回调、同槽同步递归与跨槽自关闭拒绝、发布前失败可重开、写入中断/缓存或页权限失败保留未知责任、发布成功后停车调用恢复并通过同一个mid观察。再验证真实生产metadata、IL2CPP对象持根和并发listener mutation。
4. **补齐真正的消费者闭合。** 三条实际listener调用点、动态provider转交、取消以及所有未来来源必须有明确结束事实。随后才能关闭整个run的图/root/音频/globals/menu/result资源并执行Retry、Return和Loader的完整流程；不能用本批15个fixture原调用结束代替这些条件。
