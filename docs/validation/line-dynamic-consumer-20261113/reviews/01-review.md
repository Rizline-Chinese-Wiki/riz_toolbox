## Static disposition

No remaining material defect found in the scoped v3 projection. This is a source-level disposition only. The candidate still needs a fresh isolated build and actual case execution before any integration decision.

The original Canvas aggregate calls `VerifyAppliedValues()` before and after projection. That method takes two complete rounds of Canvas cache and position readback; `RequireAppliedLineRingSource` ties the proof to the original source capture and Plan. The endpoint writer then issues a fresh applied parent/local/world record. Its `RequireIssuedWorldObservation` requires the exact latest returned object, owner, source, projection and applied nonrestoring state. The scene read uses the adopted source's original reader and checks that issued record on both sides. The consumer compares a later complete world/scene observation, including exact Single bits for current time, speed, scale and camera/UI values, before returning historical owned rows. The initial owner-thread checks and thread-static projection guard refuse worker access and synchronous reentry before native inspection; this path issues no setter or renderer call.

The consumer copies the complete bounded `dynamicLines` occurrence list, including repeated physical Line references, without requiring a Note join. It maps the physical endpoint writer rows and world tuples, rejects missing or contradictory associations, and retains each occurrence ordinal. A repeated Line must yield the same numeric buffer. An empty dynamic array yields no row even when static group lines exist. A floor or world cull yields `WouldSetPositions=false` with no position count, matching a producer branch that skips `SetPositions`.

## Two resolved source mismatches

1. **Raw floor index versus physical Canvas slot.** In frozen `LineControl.SetDynamicLines.asm.txt` (SHA-256 `f11f2cc94cb58a09f03f1944ef6a41750252f4aa951e1395b03caac9bb23395c`), `0x3ed04c/0x3ed068` and `0x3ed0a4/0x3ed0c0` use each `LinePoint.canvasIndex` directly as the `floorPositions` array index. The accepted `NativeSeekLineEndpointLocalTarget` instead matches `CanvasMove.index` by value to find the physical Transform slot. V1 incorrectly used that physical slot for the floor lookup. V3 uses `Plan.Rows[start.CanvasIndex]` and `Plan.Rows[end.CanvasIndex]` with unsigned bounds checks, while retaining the writer's physical slots for parent checks. This is supported by the accepted cache access: it creates `floorPositions[k]` targets from `Plan.Rows[k].FloorPosition`, and the Canvas aggregate verifies the complete applied cache bits twice. The new case 30 swaps `CanvasMove.index` values and uses distinct floor targets, requiring raw floor indices 0/1 with physical parent slots 1/0; its separate out-of-range case makes raw index 999 match a valid parent slot but refuses the floor projection. This addresses the specific mismatch that a fixture with `index == slot` could not expose.
2. **Line scale versus UI Transform scale.** The frozen method saves `this` (`LineControl`) in `rbx` at `0x3ecf5b`, then divides X/Y by `[rbx+0x4c]` at `0x3ed425/0x3ed441`. That field is `LineControl._gameSceneScale`. V2 supplied the distinct UI `gameSceneCanvas.localScale.X`. V3 supplies the current `scene.LineGameSceneScale` and still records the UI scale separately. The nonempty case sets Line scale 4 and UI X scale 2 and compares samples with independently computed world positions divided by camera scale 2 and Line scale 4. Canvas `Execute` cannot silently normalize this mismatch: its cache slots cover `CanvasControl` floor positions, floor speeds, X positions, now time and speed, plus selected Canvas Transforms; they do not write `LineControl._gameSceneScale`. The fixture sets both values before Canvas capture and preserves them for the source read.

The accepted pure `NativeSeekLineRingNumericMath.ProjectDynamic` supplies the already pinned floor/world culls, distance step, integer Ease samples and relative endpoint buffer. V3 feeds it current `LineControl._speed` (`+0x48`), actual applied endpoint world positions, current CameraControl scale, the corrected Line scale, and initialized owned Ease samples. Current `_nowTime` (`+0x40`) is sampled and compared for stability, but the frozen `SetDynamicLines` body does not use it in this buffer calculation. The distinct UI scale is observed rather than substituted into the math.
