## 组件关系与权限边界

已核验的磁盘普通依赖链为 `Rizline.exe → UnityPlayer.dll → winhttp.dll → RizToolbox.EngineBootstrap.dll → RizToolbox.EngineNodeKernel.dll`。17 条选定边分别为 EXE→Unity 的 `UnityMain2` 一条、Unity→Doorstop 的四项 WinHTTP、Doorstop→Bootstrap 的四项 FirstInstall ABI，以及 Bootstrap→Kernel 的八项 ABI。完整 EXE 两组依赖、Unity 十九组依赖和 Unity 原始 TLS 两个 callback 一并记录；不是只检查被选中的函数名。

生成 native profile 时，Bootstrap 尚未链接，其自身 ILT/IAT RVA 和指向自身的 EAT RVA使用受限的零占位规则。离线核验器从最终磁盘 PE 补出实际 RVA，并核对其余非零固定边。最终磁盘关系仍不证明映射地址、运行时 IAT 内容、加载器回调顺序或源函数从未执行。核验结果明确保留 `runtimeIatObserved=false`、`executionWindowProved=false` 和 `productionAdmissionProved=false`。

第五个 Doorstop 身份存在原生私有事实及 C# 独立重复检查中；没有挪用 V4 的 256 字节保留区。统一 C# 协调器共享四种物理观察入口和已捕获职责，部分采用失败与 native fault 保持 Unknown。取消调用返回不能作为取消完成证据，观察到引擎事件也不能代替对象死亡或最终资源释放证明。

安装 r4 使用最终 package r2，覆盖额外/越界/修改 payload、生成指纹关系、junction 拒绝、外来根依赖拒绝、旧深层 Kernel 迁移、重复安装、降级、卸载保留用户修改、移除旧文件后的失败恢复、持久 journal 重载与损坏备份拒绝，以及实际进程终止后恢复。较早安装 r3 的通过原件保留；安装 r1 的 PowerShell 变量遮蔽错误、r2 的 junction 环境失败也均保留。首次提升 executor 以 `C0000142` 未启动，不计为已执行测试。

cold r2 的正常进程分别在 Importer TLS、Importer DllMain、Host main 三时点读取准确 12448 字节私有 MAP 记录。每例三阶段记录相同：实际 `state=5/failure=5`、`infoReads=3`、`verifyAttempts=0`、no-write admission=2；配置、绑定、提交、源写与保护职责全为零。fixture 不调用 Bootstrap ABI，不增加公共导出，不主动 LoadLibrary。系统 WinHTTP 参考由既有私有 resolver GetInfo 提供，逐阶段核对完整固定文件 SHA、PE、系统路径、四项 EAT/RX 与已发布表，再独立调用系统 `Close(NULL)`；TLS 和 DllMain 的转发/直接调用实际均返回 FALSE/LastError 5023，验证依据是两者相等，不写死错误码。main 只 NO_PROXY Open/Close，无 HTTP 请求。

两个缺依赖进程退出 `0xC0000135` 且没有 main 原件，只计普通依赖缺失时的加载器拒绝。正常自有 Host 缺少固定游戏 Unity 链，实际 Disabled 不能被解读为生产 admission-unproven 的某个特定错误路径，也不能证明固定游戏 17 条运行时边。cold r1 的 PID 44716 虽退出 0，离线验证因错误地固定 LastError 6 而失败；其 case/bin/失败日志保留，不计为通过。

早期生产 r1 是代理入口 `_local_unwind` 链接失败，r2/r3 为 Bootstrap 严格编译问题。兼容 r2/r3 的命令字符串替换混用路径分隔符，误写旧 r1 失败目录；保留其日志，但不能将这些尝试计为独立完成构建。r4 声明的 297 个源码输入冻结为 ZIP，其 SHA256 为 `6355965368d7eae0e0aee4fe244d7dff474877f44282a39ccbb1eb24d74336ce`；这不是完整传递工具链打包。生成器随后加入 `#nullable enable`，native 源也有兼容修正，r5 已重新建立二进制与源码、profile、最终包的关系。后续 J 批可以修改活跃生命周期源码，I 批以 r5 的 `project-sources.zip` 为准，不对未来 live source 宣称不变。

## Path

### P-I01：从固定磁盘输入到关闭许可的候选

- `path_type=callflow`；`start`：固定游戏原件、Kernel 与 Doorstop 源；`goal`：产出身份可核验、权限仍关闭的候选。

- `residual_risks`：磁盘边不是运行时 IAT；TLS 与普通导入存在不等于执行顺序已证明；生产首次写入仍关闭。

### P-I02：安装迁移中断后的独立恢复

- `path_type=callflow`；`start`：合成旧版安装与候选包；`goal`：移除旧深层 Kernel 后中断，使用新进程恢复完整原集合。
- `steps`：①核对候选 payload/profile 与安装所有权（E-I07/I08，F-I03）；②worker 写入持久事务记录并实际移除旧所有文件后被终止（E-I08，F-I03）；③新 PID 从 journal 和备份恢复并核对恢复结果（E-I08，F-I03）。
- `residual_risks`：合成目录没有运行游戏或 native payload，不能证明真实 loader 中的组件生命周期。

### P-I03：从最终普通依赖到三时点只读观察

- `path_type=callflow`；`start`：自有 Host→Importer 的普通依赖及 r5 最终三个 native 组件；`goal`：在不调用 Bootstrap ABI 的前提下记录组件冷加载行为。
- `steps`：①从最终候选 SHA/PE/MAP 生成固定私有记录和系统参考合同，核验 Host→Importer→winhttp→Bootstrap→Kernel 四段普通依赖（E-I11，F-I06）；②真实系统加载器执行最终代理及 Bootstrap 后，在 Importer TLS/DllMain 读取私有记录，并比较转发/系统原地址 Close(NULL)（E-I11/I12，F-I06）；③main 读取第三份记录并只做 NO_PROXY Open/Close，父进程绑定实际 PID、原始快照哈希及独立解码（E-I11/I12，F-I06）；④分别移除 Bootstrap、Kernel 后启动两个新的自有进程，核对 `0xC0000135` 与 main 原件缺席（E-I11，F-I06）。
- `residual_risks`：缺依赖进程不证明 Bootstrap 已执行；正常 Host 没有游戏 Unity 链，只证明 Disabled 下的组件行为，不证明游戏首次写许可或任何源函数尚未运行。
