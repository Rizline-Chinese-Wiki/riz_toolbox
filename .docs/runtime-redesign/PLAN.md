# Plan: runtime-redesign

## Overview

将 riz_toolbox 收敛为 Rizline PC 专用 Mod 平台：让作者通过共享 SDK 写插件，让玩家能组合使用插件并正常游玩。保留现有功能代码与研究证据，重构主线程调度、模块激活和播放控制的验证边界。此计划由用户“你来设计整个项目”“下一步”的委托确定；采用 T2，只覆盖运行架构，不新增前端设计、脚本运行时或规划扩展。

本文是目标设计，不是已完成的产品行为。当前产品基线为 readback-provider-r3；本轮仅静态审查及文档，无构建、安装、游戏操作。旧实测未知结果保持未知。

## Goals

- 普通运行保持轻量：没有消费者的可选功能不捕获游戏资源；状态查询不隐式准备控制或进行完整映像验证。
- 建立明确的运行边界：启动安装、场景绑定、普通 Tick、控制提交、退出释放分别负责自己的工作。
- 复用已有 SDK/Core/Hosting、模块管理、能力代次、作用域及资源仲裁，降低迁移成本。
- 由一个播放会话负责当前音源、时钟和写入；操作在明确边界验证，内部包装只复核本地归属。
- 以同候选真实可用性、成本及生命周期验证交付；断言数量不换算覆盖率或完成百分比。

## Non-Goals

- 不承诺在游戏进程内隔离恶意插件，或实时发现任何外部机器码/内存改写。
- 不在本次迁移中替换整个加载器、重写游戏播放器或支持未知游戏版本。
- 不承诺旧 SDK 二进制兼容；保留有价值的服务语义，必要的接口变化一次迁移。
- 不把任意时间跳转或完整 B01–B19 的验收作为基础预览包的发布前提；它们继续作为独立未完成工作。
- 不执行已有过期实测计划，不重做相机、N1 或退休矩阵。

## Milestones

| Phase | Deliverable | Target |
| --- | --- | --- |
| D0 | 当前调用链、成本归属与新行为合同 | 本批文档和证据，产品不变 |
| M1 | Standard/Developer 两种明确运行模式；拆分 Tick 的安装证明与通道健康检查 | 空闲宿主不遍历完整原生发布图，原函数/线程/epoch/Unknown 保持 |
| M2 | 基于插件启用意愿和场景的模块计划；统一 Tick 顺序和阶段计时 | Waiting 插件可产生需求，无需求不捕获可选资源，退出仍完成责任 |
| M3 | 一次权威播放操作验证；显式命令状态与轻量观察 | 同一新包真实暂停、恢复、倍率控制返回明确结果，无分钟级主线程准备 |
| M4 | 普通安装包与开发包分开，三个实际使用场景验收 | 基础预览可交付，功能范围和未验证能力清楚可查 |
| M5 | 独立练习/Seek 模块 | 在真实判定、Hold、音符、画面和时钟重建均闭合后单独开放 |

阶段按退出条件推进，不根据历史截止日期虚构交付时间。M1 的 R01→R02 是实现顺序，二者联合签收，R02依赖模式接线产出而不等待R01全部运行验收；不发布合同只实现一半的Standard包。M1 先于可选模块大规模迁移；M3 不以减少检查次数冒充协议已经成立。

## Stakeholders

| Role | Responsibility |
| --- | --- |
| 玩家/项目所有者 | 选择使用功能，评价实际体验；不用承担内部架构取舍 |
| Mod 作者 | 使用同一候选 SDK，声明依赖/可选需求，登记资源归属 |
| 维护者/实现代理 | 实现边界、明确保障变化、验证当前字节并更新接续状态 |

## Open Questions

- **加载器替换价值待验证。** 现有部分 Hook 有首次执行前安装约束；保留当前薄入口，只有证明现成加载器能满足时序且成本更低时再迁移。此项不阻塞 M1。
- **性能预算需要同机校准。** 初始目标见 SPEC，必须报告硬件、场景、模式、消费者和实际测量区间；目标不是已测结果。
- **完整 Seek 的宿主重建入口待闭合。** Phira 等全源码播放器只能说明协调哪些状态，不能证明本游戏有相同入口；此项属于 M5。

## Current baseline
