# 底层补全计划（foundation-expansion）

> 平台负责把通用的 Mod 接入能力做稳、做全；具体玩法和功能交给各 Mod 作者自己实现。

在已有插件宿主（能加载独立包、管启停、读部分数据、收部分事件、协调颜色覆盖）的基础上，这一阶段重点补齐公共底层的覆盖面，让更多类型的 Mod 都能通过 SDK 正常工作，同时对暂不支持的能力给出明确原因，保证多插件共存时可解释、可撤销、版本兼容。

## 推进顺序

1. 先看 `PLAN.md` 里的能力覆盖表，区分已验收、部分可用和未实现项。
2. 按 `CHECKLIST.md` 的依赖推进：优先顺序为「运行时与真实事件 → 生命周期/版本/作用域 → Hook/目标/冲突机制 → 游戏公共服务 → 发布与兼容验收」。
3. 只有真正实现并验收的能力才写进正式 SDK 文档，并同步更新清单与证据。
