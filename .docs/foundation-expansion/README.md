# 底层补全计划

> 你负责让各种 Mod 都有稳定、可共用的接入方式；具体功能由 Mod 作者实现。

现在有可运行的插件宿主，已经能加载独立包、管理启停、读取部分游戏数据、接收部分事件并协调颜色覆盖。下一步要补的是公共能力的宽度和边界：让更多类型的 Mod 都可以通过 SDK 工作。

## Quick Start

1. 先读 PLAN 的覆盖表：确认哪些已验、哪些部分可用、哪些未实现。
2. 按 CHECKLIST 的依赖选择任务；先收口开局漏报，再补通用机制和游戏服务。
3. 每次只把实现并验收的能力加入正式 SDK 文档，更新清单和证据。

## Current Status

2026-10-19：第一批实现已安装为 **0.3.0 / SDK 1.2.0**。已落地原生类型校验、SDK 二进制兼容检查、子作用域/取消、实时能力描述和会话诊断；170 项自动检查、12 项安装、9 项导出检查通过。真实启动加载五个独立插件，资源覆盖/恢复、子作用域取消、10 项能力描述与证据导出通过，最终会话零警告/错误。见 [实现报告](../../docs/2026-10-19_实现-Rizline底层补全首批-report.md)。

**实际开局仍待复测**：此前用户游玩确认过场景切换和失败结算，但缺开局通知；本轮仅启动自测，不能勾选完整生命周期。B03 与 B18a 已验收；B02/B05/B06 已完成部分机制，其余任务仍按 CHECKLIST 推进。优先级是：运行时与真实事件 → 生命周期/版本/作用域 → Hook/目标/冲突机制 → 游戏公共服务 → 发布与兼容验收。

“底层覆盖广”不要求你做完所有具体 Mod。它要求常见需求有统一接入方式；暂不支持的需求有明确原因；多个插件组合后仍能解释行为、撤销修改并维护版本兼容。
