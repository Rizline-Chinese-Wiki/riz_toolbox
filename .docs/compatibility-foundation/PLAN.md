# Plan: compatibility-foundation

## Overview

将现有 RizToolbox 0.1 加载器原型推进为可由独立 Mod 作者使用的 PC 兼容底层。用户已授权“写详细任务然后开始实现”，采用标准规格文档，直接进入实施。主要使用 C#，复用已经验证的 Doorstop/CoreCLR 入口，原生桥接集中维护。所有工作在桌面 riz_toolbox 仓库进行。

## Goals

- 普通插件仅引用 SDK，独立分发，不向 Loader 添加示例类名或特例。
- 游戏适配独立于启动器；构建识别、运行时符号和能力探测集中管理。
- 插件的启用意愿、待就绪能力和故障状态分别处理；晚就绪能力能启动任意插件，用户停用后不会被自动重新启用。
- 插件依赖按目录隔离，SDK 由宿主共享；配置、面板、覆盖与订阅具有明确所有者和自动清理。
- 提供真实游戏事件与多个插件共同使用的有序扩展点，以及真实游戏资源的可撤销覆盖。
- 用独立插件、核心自动测试、打包安装检查与实际游戏运行提供证据。

## Non-Goals

- 本轮不实现工坊后端、练习模式、跨语言 IPC 或自定义谱面格式。
- 不承诺未知游戏版本自动兼容；未知构建明确拒绝适配，新增构建仅维护适配配置和实现。
- 不承诺同进程恶意插件或原生崩溃隔离；DLL 的可回收上下文不等于保证热更新。
- 不修改游戏原始 EXE、GameAssembly、存档或在线提交行为；游戏内验收不制造正式成绩。

## Milestones

| Phase | Deliverable | Target |
|---|---|---|
| M1 | SDK/Core 生命周期、作用域、扩展点、自动测试 | 任意插件晚就绪自动启动，停用完整清理 |
| M2 | 按目录插件包、依赖隔离、独立样例及构建安装 | 宿主不引用示例，冲突版本依赖可以共存 |
| M3 | 独立运行时/适配器、真实事件和资源 | 每项能力以实际探测结果声明 |
| M4 | 组合验证、安装运行及文档回写 | 按验收表逐项记录，不以占位接口计完成 |

## Stakeholders

| Role | Responsibility |
|---|---|
| 项目维护者 | 核心契约、版本策略及游戏适配 |
| Mod 作者 | 仅通过 SDK 使用服务和扩展点，按插件目录分发 |
| 实现代理 | 在授权目录实现、测试、记录实际边界 |

## Open Questions

当前无须用户决策的阻塞问题。游戏符号是否可接入、资源是否存在由本机构建探测确定；不满足时必须记录原因及尚未通过的验收项。
